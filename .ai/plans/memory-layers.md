# Plan: Memory Layers

> Source PRD: `.ai/prd/memory-layers.md`

## Архитектурные решения

- **Хранение долговременной памяти**: `~/.config/ai_challenge_agent/memory.md` (путь через `MEMORY_DIR`)
- **Хранение рабочей памяти**: `.ai/memory.md` в директории проекта
- **Формат**: простой markdown, записи разделены `\n\n---\n\n`
- **Подмешивание в контекст**: всегда, для всех стратегий, в `instructions` параметр запроса
- **Порядок приоритета в system prompt**: долговременная память → рабочая память → системный промпт
- **Конфигурация**: `MEMORY_DIR` env-переменная (дефолт `~/.config/ai_challenge_agent`)

---

## Фаза 1: Модуль памяти — чтение/запись + подмешивание в контекст

**User stories**: 11, 12, 13, 14, 16

### Что построить

Создать модуль `memory.ts` с функциями чтения и записи для двух markdown-файлов: глобальной долговременной памяти и проектной рабочей памяти. Интегрировать чтение обоих слоёв в построение system prompt (`request.ts`), чтобы содержимое памяти подмешивалось в `instructions` при каждом запросе — и в REPL, и в single-request режиме. Если файл не существует или пуст — блок не добавляется.

### Критерии приёмки

- [ ] Модуль `memory.ts` читает долговременную память из `$MEMORY_DIR/memory.md`
- [ ] Модуль `memory.ts` читает рабочую память из `.ai/memory.md`
- [ ] Модуль `memory.ts` дописывает записи в оба файла с разделителем `---`
- [ ] Автосоздание директорий и файлов при первой записи
- [ ] В `request.ts` содержимое обоих слоёв попадает в `instructions` перед системным промптом
- [ ] Пустая/отсутствующая память не добавляет пустых блоков
- [ ] Тесты на чтение/запись/отсутствие файлов (по аналогии с `db.test.ts` — временные директории)
- [ ] Тесты на корректное построение `instructions` с памятью

## Фаза 2: Команды записи — `/remember` и `/save_facts`

**User stories**: 2, 3, 15

### Что построить

Добавить в REPL две команды: `/remember <текст>` дописывает текст в глобальную долговременную память, `/save_facts <текст>` дописывает текст в рабочую память проекта. Обе используют функции записи из модуля `memory.ts`. После записи показывать подтверждение пользователю.

### Критерии приёмки

- [ ] `/remember привет` дописывает «привет» в `$MEMORY_DIR/memory.md`
- [ ] `/save_facts архитектура: monorepo` дописывает в `.ai/memory.md`
- [ ] Оба команды создают файл/директорию при первом вызове
- [ ] После записи выводится подтверждение с путём к файлу
- [ ] Вызов без аргумента показывает подсказку по использованию

---

## Фаза 3: Команды чтения и редактирования

**User stories**: 7, 8, 9, 10

### Что построить

`/memory` показывает содержимое долговременной памяти, `/facts` переназначается на показ рабочей памяти (вместо SQLite-фактов). `/edit_memory` и `/edit_facts` открывают соответствующий файл в `$EDITOR`. Если файл пуст или не существует — показать сообщение об этом.

### Критерии приёмки

- [ ] `/memory` выводит содержимое `$MEMORY_DIR/memory.md` или сообщение «пусто»
- [ ] `/facts` выводит содержимое `.ai/memory.md` или сообщение «пусто»
- [ ] `/edit_memory` открывает `$EDITOR` для долговременной памяти
- [ ] `/edit_facts` открывает `$EDITOR` для рабочей памяти
- [ ] Старая логика `/facts` (SQLite) заменена на чтение файла

## Фаза 4: Предложения по сохранению в рабочую память

**User stories**: 4, 5, 6

### Что построить

После каждого ответа ассистента отправлять дополнительный LLM-запрос: «есть ли в этом обмене что-то, что стоит сохранить в рабочую память?». Если LLM считает что есть — показать пользователю предложение с вариантами `[д]а / [н]ет / [и]зменить`. Сообщения-предложения и ответы на них не записываются в таблицу `messages`.

### Критерии приёмки

- [ ] После ответа ассистента выполняется запрос к LLM для оценки
- [ ] Если есть что сохранить — показывается предложение с текстом
- [ ] `д` — сохраняет в `.ai/memory.md` как есть
- [ ] `н` — пропускает без сохранения
- [ ] `и` — позволяет отредактировать текст перед сохранением
- [ ] Предложения и ответы НЕ попадают в таблицу `messages`
- [ ] Для запроса оценки используется модель из роли `facts` (через `getModelForRole`)

## Фаза 5: Отвязка от стратегии facts

**User stories**: (техническая задача)

### Что построить

Память подмешивается всегда, независимо от стратегии контекста — это уже сделано в фазе 1. В этой фазе нужно убрать или адаптировать стратегию `facts`: она больше не нужна как отдельная стратегия, т.к. рабочая память её заменяет. Убрать автоматическую LLM-экстракцию фактов в SQLite. Таблицу `facts` оставить для обратной совместимости (не удалять миграцией).

### Критерии приёмки

- [ ] Стратегия `facts` убрана из списка доступных стратегий (или переименована)
- [ ] Автоматическая экстракция фактов в SQLite после ответа ассистента отключена
- [ ] `/strategy` показывает только `full` и `sliding`
- [ ] Таблица `facts` в SQLite остаётся (не удаляется)
- [ ] Существующие сессии со стратегией `facts` корректно работают (fallback на `full` или `sliding`)
- [ ] Тесты обновлены
