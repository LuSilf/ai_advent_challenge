# Реконсиляция памяти (Memory Reconciliation)

## Problem Statement

В рабочую и долговременную память могут добавляться дублирующиеся факты, потому что текущий механизм просто аппендит текст без проверки существующего содержимого. Пользователь вынужден вручную редактировать файлы памяти, чтобы убрать повторы. Кроме того, стоимость LLM-запросов, связанных с управлением памятью, нигде не отображается.

## Solution

Заменить простой аппенд на пайплайн реконсиляции: LLM получает текущее содержимое памяти и новый контент (диалог или текст команды), сравнивает, формирует обновлённую версию целиком. Пользователю показывается только дельта (что добавлено/изменено). При подтверждении — полная перезапись файла. Стоимость всех memory-запросов за цикл накапливается и выводится одной строкой.

## User Stories

1. Как пользователь, я хочу чтобы при предложении сохранить в рабочую память LLM сравнивал новые факты с существующими, чтобы не было дублей
2. Как пользователь, я хочу видеть только дельту (новое и изменённое) в предложении, чтобы быстро оценить нужность
3. Как пользователь, я хочу чтобы при подтверждении файл памяти перезаписывался целиком с учётом изменений, а не аппендился
4. Как пользователь, я хочу чтобы `/remember текст` проходил через реконсиляцию: LLM сравнивает текст с долговременной памятью и предлагает обновлённую версию
5. Как пользователь, я хочу чтобы при пустой памяти запись происходила без LLM-запроса (экономия токенов)
6. Как пользователь, я хочу видеть стоимость memory-операций после каждого цикла работы с памятью: «Фактов не обнаружено: стоимость», «Сохранено в рабочую память: стоимость», «Факты отклонены: стоимость»
7. Как пользователь, я хочу настраивать интервал предложений рабочей памяти (каждые N пар сообщений) через опцию
8. Как пользователь, я хочу чтобы при переключении сессии (`/new`, `/switch`) или выходе (`/exit`) работа с рабочей памятью запускалась всегда, независимо от интервала
9. Как пользователь, я хочу чтобы при `/new`, `/switch`, `/exit` переключение/выход блокировались до завершения процесса реконсиляции и подтверждения
10. Как пользователь, я хочу хранить настройки ассистента в БД и менять их через REPL-команды
11. Как пользователь, я хочу видеть текущие настройки командой `/options`
12. Как пользователь, я хочу менять настройку командой `/set ключ значение`
13. Как пользователь, я хочу чтобы формат памяти оставался свободным markdown — LLM формирует обновлённый документ целиком
14. Как пользователь, я хочу принять, отклонить или отредактировать предложенные изменения памяти (д/н/и)

## Implementation Decisions

### Пайплайн реконсиляции

Один LLM-запрос, который получает:
- Текущее содержимое файла памяти (рабочей или долговременной)
- Новый контент (последний обмен сообщениями для рабочей памяти, или текст из `/remember` для долговременной)

LLM возвращает JSON с двумя полями:
- `updated_memory` — полный обновлённый текст файла памяти (свободный markdown)
- `changes_summary` — краткое описание что изменилось (для показа пользователю)

Если `changes_summary` пустой или LLM явно указывает отсутствие изменений — пользователю ничего не показывается.

### Оптимизация: пустая память

Если файл памяти пуст или не существует:
- Для рабочей памяти: LLM-запрос на извлечение фактов из диалога (без сравнения), но формат ответа тот же
- Для `/remember текст`: запись текста напрямую, без LLM-запроса

### Перезапись вместо аппенда

При подтверждении пользователем файл памяти перезаписывается целиком содержимым `updated_memory`. Функция `appendToMemoryFile` остаётся для обратной совместимости, добавляется `writeMemoryFile` для полной перезаписи.

### Аккумулятор стоимости

Объект, который накапливает `input_tokens` и `output_tokens` за все LLM-запросы в рамках одного цикла работы с памятью. После завершения цикла выводится одна строка с итогом и статусом:
- `💡 Фактов не обнаружено: $0.000045 (320 in / 15 out)`
- `💡 Сохранено в рабочую память: $0.000123 (450 in / 30 out)`
- `💡 Факты отклонены: $0.000123 (450 in / 30 out)`

### Настройки в БД

Новая таблица `options` в SQLite:
- `key TEXT PRIMARY KEY` — имя опции
- `value TEXT NOT NULL` — значение

Начальные опции:
- `memory_interval` — интервал предложений рабочей памяти в парах сообщений (дефолт: `5`)

REPL-команды:
- `/options` — показать все настройки с текущими значениями
- `/set ключ значение` — установить значение настройки

### Счётчик сообщений

В REPL хранится счётчик пар сообщений с последнего запуска реконсиляции. При достижении `memory_interval` — запускается пайплайн. Счётчик сбрасывается после запуска (независимо от результата).

### Триггеры при смене сессии

Команды `/new`, `/switch`, `/exit` перед выполнением основного действия запускают реконсиляцию рабочей памяти (если были сообщения с последнего запуска). Выполнение команды блокируется до завершения реконсиляции и подтверждения пользователем.

### Модули

1. **Модуль реконсиляции** — функция, принимающая текущую память, новый контент, тип памяти; отправляющая LLM-запрос; возвращающая результат (updated_memory, changes_summary, usage)
2. **Модуль настроек** — CRUD для таблицы `options` в SQLite
3. **Аккумулятор стоимости** — простой объект-счётчик с методами add/format/reset
4. **Обновлённый memory.ts** — добавить `writeMemoryFile` (полная перезапись)
5. **Обновлённый REPL** — новая логика `/remember`, триггеры при смене сессии, счётчик сообщений

## Testing Decisions

Хороший тест проверяет внешнее поведение модуля через его публичный интерфейс, не завися от деталей реализации.

### Что тестировать

- **Модуль реконсиляции** — парсинг JSON-ответа LLM (валидный, невалидный, с code block), обработка случая «нет изменений», обработка пустой памяти
- **Модуль настроек** — CRUD операции (get/set/list), дефолтные значения, несуществующие ключи
- **Аккумулятор стоимости** — накопление нескольких запросов, форматирование вывода, сброс
- **Обновлённый memory.ts** — `writeMemoryFile` корректно перезаписывает файл

### Аналоги в кодовой базе

- `memory.test.ts` — тесты на чтение/запись с временными директориями
- `db.test.ts` — тесты на хранилище
- `repl.test.ts` — тесты на REPL-команды через `handleCommand`

## Out of Scope

- Автоматическая реконсиляция долговременной памяти (только по команде `/remember`)
- Семантический поиск по памяти
- Конфликт-резолюция между рабочей и долговременной памятью
- Лимит на размер файлов памяти
- Настройки через env-переменные (только БД)
- Миграция существующего содержимого памяти в новый формат

## Further Notes

- LLM-промпт для реконсиляции должен явно инструктировать: не удалять существующие факты без причины, обновлять изменившиеся, добавлять новые
- JSON-формат ответа (`updated_memory` + `changes_summary`) позволяет чётко разделить данные для файла и для пользователя
- Формат памяти остаётся свободным markdown — LLM сам решает как структурировать
- При ошибке LLM-запроса (таймаут, невалидный ответ) — показать ошибку, не блокировать работу
