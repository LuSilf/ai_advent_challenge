# Реестр моделей и учёт стоимости

## Problem Statement

Сейчас модель задаётся через env-переменную как строка. Нет информации о стоимости, размере контекста и ограничениях. Невозможно понять, сколько стоит каждый запрос. Для разных задач (чат, заголовки, экстракция фактов) нет удобного способа назначить разные модели.

## Solution

Таблица моделей в SQLite с предзаполненными данными: id модели (как в API OpenRouter), отображаемое имя, цена за input/output на 1M токенов, размер контекста. Отдельная таблица маппинга ролей на модели. После каждого запроса — показ стоимости на основе использованных токенов.

## User Stories

1. Как пользователь, я хочу видеть стоимость каждого запроса после ответа ассистента, чтобы контролировать расходы
2. Как пользователь, я хочу назначать разные модели для разных задач (чат, заголовки, экстракция фактов), чтобы оптимизировать стоимость
3. Как пользователь, я хочу переключать модель для роли через REPL-команду, чтобы не перезапускать приложение
4. Как пользователь, я хочу видеть список доступных моделей с ценами и контекстом
5. Как пользователь, я хочу видеть какая модель назначена на какую роль
6. Как пользователь, я хочу чтобы при старте приложения таблица моделей была предзаполнена актуальными данными
7. Как пользователь, я хочу чтобы размер контекста модели учитывался при построении запроса, чтобы не превышать лимит
8. Как пользователь, я хочу чтобы стоимость показывалась в удобном формате (центы/доллары) после каждого ответа

## Implementation Decisions

### Схема БД

Новая таблица `models`:

| Поле | Тип | Описание |
|------|-----|----------|
| id | TEXT PRIMARY KEY | ID модели для API (например `openai/gpt-5-nano`) |
| name | TEXT NOT NULL | Отображаемое имя (например `GPT-5 Nano`) |
| input_price | REAL NOT NULL | Цена input за 1M токенов в USD |
| output_price | REAL NOT NULL | Цена output за 1M токенов в USD |
| context_size | INTEGER NOT NULL | Размер контекста в токенах |

Новая таблица `model_roles`:

| Поле | Тип | Описание |
|------|-----|----------|
| role | TEXT PRIMARY KEY | Роль: `chat`, `title`, `facts` |
| model_id | TEXT NOT NULL REFERENCES models(id) | Назначенная модель |

### Предзаполнение

При инициализации БД (миграции) вставляются модели через `INSERT OR IGNORE`:

| ID | Имя | Input $/1M | Output $/1M | Контекст |
|----|-----|-----------|-------------|----------|
| `openai/gpt-5-nano` | GPT-5 Nano | 0.05 | 0.40 | 400 000 |
| `openai/gpt-5.4-nano` | GPT-5.4 Nano | 0.20 | 1.25 | 400 000 |
| `google/gemini-2.5-flash-lite` | Gemini 2.5 Flash Lite | 0.10 | 0.40 | 1 048 576 |
| `qwen/qwen3-235b-a22b-2507` | Qwen3 235B A22B | 0.071 | 0.10 | 262 144 |
| `qwen/qwen3.5-flash-02-23` | Qwen3.5 Flash | 0.065 | 0.26 | 1 000 000 |
| `deepseek/deepseek-v3.2` | DeepSeek V3.2 | 0.26 | 0.38 | 163 840 |
| `xiaomi/mimo-v2-flash` | MiMo V2 Flash | 0.09 | 0.29 | 262 144 |

Дефолтные маппинги ролей (через `INSERT OR IGNORE`):

| Роль | Модель |
|------|--------|
| `chat` | `openai/gpt-5-nano` |
| `title` | `openai/gpt-5-nano` |
| `facts` | `openai/gpt-5-nano` |

### Использование вместо env-переменных

- `OPENAI_MODEL` и `TITLE_MODEL` удаляются из конфига, модели берутся только из таблицы `model_roles`
- При построении запроса модель берётся из БД по роли
- `context_size` модели используется для ограничения количества токенов в контексте

### Подсчёт стоимости

- После получения ответа от API берётся usage (input_tokens, output_tokens)
- По `model_id` из таблицы `models` вычисляется стоимость: `(input_tokens / 1_000_000) * input_price + (output_tokens / 1_000_000) * output_price`
- Стоимость выводится после каждого ответа в формате: `💰 $0.0023 (1234 in / 567 out)`
- Если debug-режим включён — дополнительно показываются детали (модель, цены, токены)

### Команды REPL

- `/models` — показать список всех моделей с ценами и контекстом
- `/roles` — показать текущий маппинг ролей на модели
- `/set_model <роль> <model_id>` — назначить модель на роль (например `/set_model chat deepseek/deepseek-v3.2`)

### Конфигурация

- `OPENAI_MODEL` и `TITLE_MODEL` удаляются из конфига — модели берутся только из таблицы `model_roles`
- Дефолтная модель для всех ролей: `openai/gpt-5-nano`

## Testing Decisions

Хороший тест проверяет внешнее поведение модуля через его публичный интерфейс.

### Что тестировать

- **CRUD моделей** — предзаполнение, получение модели по id, получение списка
- **Маппинг ролей** — получение модели по роли, смена модели для роли, валидация что model_id существует в таблице models
- **Расчёт стоимости** — корректность вычисления по формуле, форматирование вывода

### Аналоги в кодовой базе

- `db.test.ts` — тесты на хранилище с in-memory SQLite

## Out of Scope

- REPL-команды для добавления/удаления моделей
- Автоматическое обновление цен с OpenRouter API
- Накопление статистики расходов по сессиям / за период
- Учёт кешированных токенов в стоимости
- Автоматический выбор оптимальной модели по задаче

## Further Notes

- Цены актуальны на дату составления PRD (2026-03-31) и могут измениться
- Все модели доступны через OpenRouter, base_url остаётся настраиваемым
- Формула стоимости не учитывает reasoning-токены (если появятся — расширить)
