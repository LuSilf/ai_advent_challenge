# Сценарий тестирования: Планировщик и фоновые задачи

## Подготовка

```bash
# Убедиться что .env настроен
cat .env

# Убедиться что тесты проходят
bun test
```

---

## 1. REPL-команды: CRUD

### 1.1 Создание задачи (cron в кавычках)
```
/schedule create "*/1 * * * *" Скажи короткий факт о космосе
```
**Ожидание:** `Задача #N создана`, cron и следующий запуск отображаются.

### 1.2 Создание задачи (interval shortcut)
```
/schedule create every 5m Расскажи анекдот
```
**Ожидание:** Задача создана, cron конвертирован в `*/5 * * * *`.

### 1.3 Создание задачи (невалидный cron)
```
/schedule create "99 99 99 99 99" тест
```
**Ожидание:** Ошибка `Невалидное cron-выражение`.

### 1.4 Список задач
```
/schedule list
```
**Ожидание:** Таблица с id, статусом вкл/выкл, именем, cron, следующим запуском.

### 1.5 Выключение задачи
```
/schedule disable 1
/schedule list
```
**Ожидание:** Задача #1 отображается как `[выкл]`.

### 1.6 Включение задачи
```
/schedule enable 1
/schedule list
```
**Ожидание:** Задача #1 снова `[вкл]`, `next_run_at` пересчитан.

### 1.7 Удаление задачи
```
/schedule delete 1
/schedule list
```
**Ожидание:** Задача #1 исчезла из списка.

### 1.8 Удаление несуществующей
```
/schedule delete 999
```
**Ожидание:** `Задача #999 не найдена`.

### 1.9 Справка
```
/schedule help
```
**Ожидание:** Список подкоманд.

## 2. Автоматическое выполнение (тик-цикл)

### 2.1 Задача выполняется по расписанию
```
/schedule create "*/1 * * * *" Скажи одно слово
```
**Действие:** Подождать ~1 минуту, не вводя ничего.

**Ожидание:** В REPL появляется цветной блок:
```
 Задача: Скажи одно слово
<ответ LLM>
```

### 2.2 Результат записывается в историю
```
/schedule results
```
**Ожидание:** Запись с временем, `success`, количеством tokens и preview ответа.

### 2.3 Результаты по конкретной задаче
```
/schedule results 1
```
**Ожидание:** Только выполнения задачи #1.

### 2.4 Выключенная задача не выполняется
```
/schedule disable 1
```
**Действие:** Подождать 1+ минуту.

**Ожидание:** Новых выполнений задачи #1 не появляется.

## 3. LLM tool-use (natural language)

### 3.1 Создание через промпт
```
Каждые 10 минут проверяй погоду и сообщай температуру
```
**Ожидание:**
- LLM вызывает `scheduler__create_schedule`
- В выводе видно tool call с параметрами (name, cron, prompt)
- Задача появляется в `/schedule list`

### 3.2 Просмотр через промпт
```
Покажи мои запланированные задачи
```
**Ожидание:** LLM вызывает `scheduler__list_schedules`, показывает список.

### 3.3 Удаление через промпт
```
Удали задачу с погодой
```
**Ожидание:** LLM вызывает `scheduler__delete_schedule` с правильным id.

## 4. Буферизация вывода

### 4.1 Результат не прерывает ответ LLM
**Подготовка:** Создать задачу с `*/1 * * * *`.

**Действие:** Отправить длинный промпт ("напиши эссе о космосе") так, чтобы LLM отвечал в момент срабатывания задачи.

**Ожидание:** Ответ LLM завершается полностью, затем выводится результат задачи.

## 5. Standalone scheduler

### 5.1 Запуск
```bash
# Сначала создать задачу через REPL
# Затем:
bun run scheduler
```
**Ожидание:**
- Выводится список задач и их расписание
- При срабатывании — цветной вывод в терминал
- Приходит notify-send нотификация (если notify-send установлен)

### 5.2 Graceful shutdown
**Действие:** Нажать Ctrl+C.

**Ожидание:** `Остановка...`, процесс завершается без ошибок.

### 5.3 Нет задач
```bash
# Удалить все задачи через REPL, затем:
bun run scheduler
```
**Ожидание:** Ошибка `Нет активных задач`.

## 6. MCP-tools при выполнении задачи

### 6.1 Задача с MCP tool
**Подготовка:**
```
/mcp add git bun run scripts/git-analyzer-server.ts
/schedule create "*/1 * * * *" Покажи последние 3 коммита в репозитории
```
**Действие:** Подождать выполнения.

**Ожидание:** LLM вызывает `git_log` tool и возвращает коммиты. Результат виден в `/schedule results`.

---

## 7. Обработка ошибок

### 7.1 LLM недоступен
**Действие:** Временно испортить OPENAI_API_KEY, подождать выполнения задачи.

**Ожидание:**
- Ошибка выводится красным блоком
- В `/schedule results` запись со статусом `error` и текстом ошибки
- Задача не отключается, следующий запуск пересчитан

## 8. Сессии

### 8.1 Задачи привязаны к сессии
```
/schedule create "*/5 * * * *" тест
/new
/schedule list
```
**Ожидание:** В новой сессии список задач пуст (задача принадлежит предыдущей сессии).
